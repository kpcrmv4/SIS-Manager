## กฎธุรกิจ

### ฝากเหล้า (ลอจิก Davis + แก้จุดที่พัง)
- สถานะ: `requested` (ลูกค้าขอผ่าน LINE) → `pending_confirm` (staff รับขวดแล้ว) → `in_store` (bar ยืนยัน) → `pending_withdrawal` → `withdrawn`
  · `in_store` เลยกำหนดรับคืน → `expired` → `disposed` (bar/owner กดจำหน่ายออก) · ปฏิเสธ/ยกเลิก → `cancelled` **ผลเดียวทุกหน้าจอ**
- เปลี่ยนสถานะผ่าน RPC ฝั่ง DB เท่านั้น (ห้ามเขียน status จาก client) — แต่ละ transition = หนึ่งฟังก์ชัน atomic + บันทึก `deposit_events`
- รหัสฝาก `DEP-{branch.code}-{5 ตัว A-Z0-9}` สร้างใน DB พร้อม retry เมื่อชน
- อายุฝากตั้งต่อสาขา (ค่าเริ่มต้น 30 วัน) · VIP = ไม่หมดอายุ · ต่ออายุ/VIP เฉพาะ bar และ owner
- หมดอายุ = วันที่ (เวลาไทย) · **รับคืนได้ถึง 04:00 น. ของวันถัดไป** เลื่อนข้ามวันงดเบิกของสาขา (ค่าเริ่มต้นศุกร์/เสาร์) — พอร์ต `private.deposit_collection_deadline` จาก Davis
- วันงดเบิก: เบิกดื่มในร้านไม่ได้ แต่เบิกกลับบ้านได้ (ตาม Davis)
- เบิกทีละขวดเต็ม (ไม่มีเบิกเป็น %) · พอร์ต `complete_deposit_withdrawals`
- bar ยืนยันขวด: ใส่ % ทุกขวด + รูปบังคับ · 0% = consumed · < 100% = opened
- ขวดที่มีคำขอเบิกค้างไม่ถูกหมดอายุอัตโนมัติ (ตาม Davis)
- ไม่มีสต๊อก: `liquor_items` เป็นรายการให้เลือก (ต่อสาขาหรือทุกสาขา) · deposit เก็บ `item_id` + snapshot ชื่อ · พิมพ์ชื่อเองได้ถ้าไม่มีในรายการ
- ไม่มีคลังกลาง ไม่มีโอนสาขา

### จองโต๊ะ (ใหม่)
- ลูกค้าจองผ่าน LIFF หรือพนักงานคีย์แทน (source `line` / `staff`)
- ตั้งค่าต่อสาขา: เปิดรับจองผ่าน LINE · ยืนยันอัตโนมัติ (ปิด = ร้านยืนยันก่อน) · เปิดจองล่วงหน้า N วัน (14) · ปิดรับจองของคืนนั้นเวลา (18:00) · รอบเวลา (19:00–23:00 ทุก 30 นาที) · จองสูงสุดต่อคืน (โต๊ะ) · จำนวนคนต่อการจอง (min–max) · นับไม่มาเมื่อเลยเวลา N นาที (30) · ลูกค้ายกเลิกเองได้ก่อนเวลาจอง N ชั่วโมง (2) · วันปิดประจำสัปดาห์ · วันปิดจากปฏิทินพร้อมเหตุผล
- สถานะ: `pending` → `confirmed` → `arrived` · `no_show` (cron ตามเวลาที่ตั้ง) · `cancelled` (ลูกค้า/ร้าน) · `rejected` (ร้าน)
- เลขจอง `BK-{MMDD}-{ลำดับ 3 หลักของสาขาในคืนนั้น}` + `qr_token` สุ่ม (QR เข้ารหัส token ไม่ใช่เลขจอง)
- ลูกค้าเลือกได้แค่โซน (เฉพาะโซนที่เปิดให้จองผ่าน LINE) · ร้านจัดโต๊ะ · ไม่มีมัดจำ (เฟสหลัง)
- เช็กอิน: สแกน QR หรือพิมพ์เลขจอง/เลขโต๊ะ → แสดงขวดฝากของลูกค้าคนนี้ (จับคู่ด้วย LINE user หรือเบอร์โทร)

### LINE
- แต่ละสาขามี LINE OA ของตัวเอง · token/secret อยู่ในตารางที่ `authenticated` อ่านไม่ได้ (แก้ช่องโหว่ Davis)
- แจ้งลูกค้า: ยืนยันฝาก · ใกล้หมดอายุ (N วันก่อน ค่าเริ่มต้น 7) · หมดอายุ · จำหน่ายออก · เบิกสำเร็จ/ถูกปฏิเสธ · จองยืนยัน/ถูกปฏิเสธ/ยกเลิก · เตือนวันจอง
- แจ้งกลุ่มพนักงานของสาขา: คำขอฝาก · คำขอเบิก · การจองใหม่ที่รอยืนยัน
- ทุกข้อความผ่าน `line_outbox` ที่มี `dedupe_key` unique → ส่งครั้งเดียวต่อเหตุการณ์ (แก้บั๊ก Davis ที่ส่งไม่ออก/ส่งซ้ำ)
- ข้อความลูกค้าเป็นภาษาของลูกค้า (th/en/zh/ko) · webhook ต้องมี channel secret เสมอ (Davis รันแบบไม่ตรวจลายเซ็นเมื่อไม่มี secret)

### พิมพ์
- ใบรับฝาก + ป้ายขวดผ่าน `print_jobs` + print-server เดิมของ Davis (Node + Puppeteer + SumatraPDF, 80 มม.) — ตัดส่วน transfer/Return HQ
- ใบรับฝากมี QR ของรายการนั้น (เปิดรายละเอียดฝั่งพนักงาน / ลูกค้าสแกนเพื่อเชื่อม LINE)
